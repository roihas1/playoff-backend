Verdict: right direction, narrower scope

The original canvas's core idea (parameterize series length, unify stages, add groups) is correct. It should be scoped down: you don't need Swiss systems or a plugin-style stage engine — just two stage types, KNOCKOUT and GROUP, each with an admin-editable rule set (bestOf per round; group size/points/draws/advance-count). That combination, plus treating stages as an ordered repeatable list, covers all six competitions below — including EuroLeague's mixed Play-In/Final-Four format and the FIBA World Cup's double group stage.

This app is postseason-only for league-style competitions

The "regular season / group stage" column above describes the real-world competition for context. For Israeli League, EuroLeague, and NBA, this app never creates a stage for that part — it only models the knockout bracket. A GROUP stage is only created for competitions that have a real simultaneous group phase feeding a bracket (World Cup, EuroBasket, FIBA World Cup's double group stage).

Still just 2 stage types, now proven against 6 real competitions

None of these six formats — including EuroLeague's Play-In/Final-Four mix and the FIBA World Cup's double group stage — need a third stage type. They need: (1) an ordered list of KNOCKOUT/GROUP stages with no fixed count, (2) per-round bestOf inside a knockout stage, and (3) a bracket depth/seed range that scales with team count instead of being capped at 8.

Already generic: points aggregation

Fantasy points are already a column on every bet row, and scoring already sums whatever exists (teamWin.fantasyPoints + bestOf7.fantasyPoints + each matchup.fantasyPoints) with no hardcoded weighting. The only hardcoded part is the creation-time defaults (4 and 6) and the fact that every series always gets both bet types — both move into the round/group config above, nothing in the scoring/aggregation code needs to change.

Admin configuration flow (target)

1. Create tournament: Name, year, sportType — unchanged from today

2. Add stage(s) in order: Pick KNOCKOUT or GROUP per stage (e.g. World Cup = Group then Knockout; Euroleague = Knockout only)

3a. Configure a KNOCKOUT stage: Add rounds in order, each with a label and bestOf (e.g. Quarterfinal/Bo5, Semifinal/Bo5, Final/Bo7)

3b. Configure a GROUP stage: Set group size, number of groups, points for win/draw/loss, allow-draws toggle, advance-count per group

4. Assign teams: Assign teams to round-1 knockout matchups or to groups — reuses existing series-creation flow

5. Run the stage: Group: fixtures update standings automatically. Knockout: series close as today, admin advances winners into the next round

6. Hand off to the next stage: Same manual step regardless of the combination — top group finishers into another Group stage (FIBA World Cup) or into a Knockout stage (FIFA), auto-seeding is the only stretch item

Explicitly out of scope

A generic N-stage-type plugin engine (Swiss, ladder, round-robin league, etc.) — only KNOCKOUT and GROUP are modeled

Automatic support for every sport's scoring quirks (extra time, penalty shootouts as separate entities) — a knockout match is still one Series with a final winner

Fully automated bracket seeding from group results in v1 — kept manual first, automated as a later stretch phase

Design rule to hold the line on

Series stays exactly 2 teams for every format. Group stages are many Series fixtures plus a standings projection, not a wider entity. Knockout rounds carry their own bestOf, so a final can be longer than earlier rounds. Everything else — draws, group size, points rules, bracket size — is data an admin sets per tournament, not a code branch.
